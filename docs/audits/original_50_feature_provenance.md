# 原50特征表来源核查

用户确认5_data指当前项目的5_实验数据。

## 已确认

- 5_实验数据有1008个文件：526个txt、312个png、166个jpg、2个xlsx、2个db。
- 两个xlsx为指围信息_all.xlsx和inbody770_data_all.xlsx；未找到筛选代码、50特征表、逐折特征名单或生成日志。
- 原始扫描图存在于该Git忽略目录中；此前仅用默认rg文件列表查图像漏掉了这个目录。原纹理特征提取器仍未找到。
- 当前固定50特征表位于feature-enginnering/linear-features/experiment1.0-50features/X_结合相关互相关_spe_0.9_rfr_50.xlsx，包含128行、32名受试者、50个特征和3个元数据列；只有Sheet1，无折标记。xlsx属性中的创建时间为2024-04-22，但属性时间不能证明生成算法。

## 现存代码证据

- features_props_jiehe_rfr.py在17–25行读取整表标签与特征，34行fit(data,tags)，35–39行排序并导出，无交叉验证循环。当前参数num=35，输入是已有50表，因此不是原始生成50表的原样快照。
- features_props_jiehe_rfr_fenji.py和features_props_jiehe_rfr_standard.py也读取整表、整表拟合再截取特征，当前分别取25和35；它们同样不是原50表生成的完整证据。
- features_props_jiehe_spearman_xghxg.py读取已计算的整张相关性表及特征互相关表，依据目标相关性去重，并导出固定结果，没有逐折重算。
- eval_feature_count_accuracy_cross.py在67–70行全局缩放及全数据标签排序后，84行才调用跨被试验证，明确属于先统一筛选、再验证的旧评估方式。
- overfit_validation_nestedcv_binary.py声称加载大特征表并在每个训练折取Top50；但path_utils.py把大表名及50表名均映射至同一份固定50表。实时解析确认两者均为128×50特征输入。因此每折从50中取50，不能证明原50是在折内从完整候选池发现。

## 判断与边界

现存旧筛选代码与评估链路支持“固定候选表先统一筛选，再进行五折评估”的判断，没有找到原50是在五折训练折内生成的证据。

但当前仓库缺少原50的直接生成脚本版本/命令/日志，仅有后续缩减脚本和输出表，因此不能完全确认2024年那次导出采用了什么参数和划分。表中有全部128行本身也不能证明全数据参与特征选择。

返修时不能把该固定50表直接认定为无泄漏候选池。应从筛选前的完整特征表在训练折内重做筛选；若要恢复原版流程，需要原50生成时的脚本或运行记录。
